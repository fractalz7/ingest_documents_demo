# Spec: agentic policy-conflict ingestion demo, with evals

Status: draft v1 for implementation by a cost-efficient model. Authoritative data contract: `pcd/schemas.py` (do not edit it).

## 1. Purpose and non-goals

Build a small, runnable, fully offline demo of the ingestion design: agents **propose and verify**, deterministic code **decides**, and an eval harness scores the whole thing against synthetic cases with known ground truth.

In scope: pipeline, rules engine, stub backends, eval harness, a case generator, 10 sample cases, tests.
Out of scope for this milestone: live LLM calls in tests, UI, MCP server, graph database, the 100-case set, a single-call baseline. A CrewAI adapter is written but marked UNTESTED.

All data is synthetic. Owners are `PAYER` and `CARE_DELIVERY`. Every generated document ends with the line `SYNTHETIC TEST DOCUMENT`.

## 3. Pipeline (pcd/pipeline.py)

`run_case(case, backend, reviewer, config) -> PipelineResult`. `PipelineConfig(use_verifier: bool = True)`.

Steps for one case (a case is a small corpus of documents):

1. **Metadata gate.** For each document call `backend.classify(doc)`. If it returns `None`, add the doc id to `blocked_docs` and skip it entirely.
2. **Extract.** `backend.extract(doc, meta)` returns a list of `Claim`. `claim_id` is `f"{doc_id}:{topic}"`.
3. **Candidate pairs.** Every pair of claims from different docs with the same `topic`. Order pairs by `(claim_a_id, claim_b_id)` with `claim_a_id < claim_b_id`.
4. **Detect.** `backend.detect(a, b)` returns a `PairJudgement` (label).
5. **Verify** (if `use_verifier`). `backend.verify(a, b, judgement)` returns a `Verdict`. `verifier_disputed = not verdict.agrees`.
6. **Computed facts** (deterministic, from the extracted claims): `scope_overlap`, `date_overlap`, `values_differ = a.value != b.value`.
7. **Consistency guardrail.** Set `inconsistent = True` when the agent label contradicts the computed facts:
   - label in `{TRUE_CONTRADICTION, OUTDATED_VERSION, AMBIGUITY_TIE}` but not (`scope_overlap` and `date_overlap` and `values_differ`), or
   - label in `NONCONFLICT_LABELS` but (`scope_overlap` and `date_overlap` and `values_differ`).
8. **Route.**
   - If label is in `NONCONFLICT_LABELS` and not `inconsistent` and not `verifier_disputed`: route `NONE`, both claims `CERTIFIED`.
   - Otherwise compute `resolution = rules.decide_resolution(a, b)` and `checks = rules.compute_checks(a, b, resolution)`. Route is `AUTO` only if all three checks are true **and** not `inconsistent` **and** not `verifier_disputed`. Otherwise `HUMAN`.
9. **Settle.**
   - `AUTO`: statuses from `rules.statuses_from_resolution`.
   - `HUMAN`: call `reviewer.decide(case_id, a, b, resolution)` which returns the pair's final status dict. The proposal text comes from `backend.propose_text(a, b, resolution)` and is stored on the `PairResult`. The reviewer is simulated in the demo.
   - `NONE`: both `CERTIFIED`.
10. **Aggregate.** A claim's final status is the most restrictive status across all its pairs (`WITHHELD` > `SCOPED` > `CERTIFIED`). A claim in no pair is `CERTIFIED`. Claims from blocked docs do not appear.

The routing is code. No agent output can cause a `HIGH`-risk topic to be routed `AUTO`. This is a tested invariant (section 9).

## 4. Rules engine (pcd/rules.py), deterministic, no randomness

- `scope_overlap(a: Scope, b: Scope) -> bool`: true when, for every dimension (plan, state, setting), the values are equal or either is `ANY`.
- `date_overlap(a: Claim, b: Claim) -> bool`: intervals `[effective_start, effective_end or +infinity]` intersect, inclusive.
- `specificity(s: Scope) -> int`: number of dimensions that are not `ANY`.
- `scope_covers(winner: Scope, loser: Scope) -> bool`: for every dimension, `winner == ANY` or `winner == loser`.
- `decide_resolution(a: Claim, b: Claim) -> Optional[Resolution]`, first matching rule wins:
  - **R1_SUPERSEDES**: if `a.supersedes_doc_id == b.doc_id`, `a` wins (and symmetrically).
  - **R2_AUTHORITY**: the higher `authority` wins.
  - **R3_SCOPE**: equal authority: the higher `specificity` wins.
  - **R4_DATE**: equal authority and specificity: the later `effective_start` wins.
  - If none distinguishes the claims, return `None` (a tie).
  - `loser_disposition = SCOPED` if `not scope_covers(winner.scope, loser.scope)` else `WITHHELD`.
- `compute_checks(a, b, resolution) -> Checks`:
  - `rule_applies = resolution is not None`
  - `low_risk = TOPICS[a.topic] == Risk.LOW`
  - `no_cross_owner_tie = not (a.authority == b.authority and a.owner != b.owner)`
- `statuses_from_resolution(a, b, resolution) -> dict[str, Status]`: winner `CERTIFIED`, loser gets `loser_disposition`. If `resolution is None`, both `WITHHELD`.

## 5. Backends (pcd/backends)

`Backend` protocol (`base.py`), with a `name: str` and a `usage` property returning `Usage`:

```
classify(doc: Document) -> Optional[DocumentMetadata]
extract(doc: Document, meta: DocumentMetadata) -> list[Claim]
detect(a: Claim, b: Claim) -> PairJudgement
verify(a: Claim, b: Claim, judgement: PairJudgement) -> Verdict
propose_text(a: Claim, b: Claim, resolution: Optional[Resolution]) -> str
```

`Reviewer` protocol: `decide(case_id, a, b, resolution) -> dict[str, Status]`.

**OracleBackend(cases)**: looks up gold by `doc_id` and `(claim_a_id, claim_b_id)`. Returns gold exactly. Verifier always agrees. Text is a fixed template. Usage: add fixed fake token counts per call.

**OracleReviewer(cases)**: returns the gold `final_status` for the pair. This models a policy owner who is always right, and who corrects agent errors that reach the queue.

**NoisyBackend(cases, seed=0, classify_error=0.05, extract_scope_error=0.10, extract_value_error=0.05, detect_label_error=0.15, verifier_catch_rate=0.60, verifier_false_dispute=0.05)**: wraps the oracle and injects errors:
- randomness via `random.Random(f"{seed}:{stage}:{key}")` so runs are reproducible and independent of call order;
- `classify_error`: change `authority` to a different level;
- `extract_scope_error`: change one scope dimension to a different plausible value (for example `FL` to `TX`);
- `extract_value_error`: change the normalized value;
- `detect_label_error`: replace the label with a different label;
- `verify`: if the judgement label is wrong, dispute with probability `verifier_catch_rate`; if right, dispute with probability `verifier_false_dispute`.

**CrewAIBackend** (`crewai_backend.py`): the real thing, written from the current CrewAI docs (https://docs.crewai.com), with Pydantic structured outputs per task. Guard the import so the module imports without crewai installed. Read the model name from the `DEMO_LLM_MODEL` environment variable and any key from the environment. Never hard-code keys. The module docstring must say **UNTESTED: not exercised by the test suite**. If you are not sure of a CrewAI API detail, leave a `TODO(verify)` comment instead of guessing.

## 6. Eval harness (pcd/evals)

`metrics.py` is pure functions over `(cases, results)`:

- `wilson_interval(k, n, z=1.96) -> (low, high)`; `n == 0` returns `(0.0, 1.0)`. Check: `wilson_interval(8, 10)` is about `(0.490, 0.943)`.
- **Extraction:** for each gold claim, match the extracted claim by `claim_id`. Report accuracy per field (`topic`, `value`, `plan`, `state`, `setting`, `authority`, `owner`, `effective_start`, `effective_end`) and `claim_recall` (gold claims found) and `claim_precision`.
- **Detection:** over gold pairs. Per-label precision, recall and F1, plus a confusion matrix. Headline numbers: `true_contradiction_recall`, and `false_conflict_rate` = fraction of gold `NONCONFLICT_LABELS` pairs where the agent predicted a conflict label.
- **Routing:** `routing_accuracy` vs gold `route`; `risky_auto_resolved` = count of pairs on `HIGH`-risk topics routed `AUTO` (target 0); `escalation_rate`; `false_escalations` (gold `AUTO` or `NONE` but routed `HUMAN`).
- **End to end:** `wrong_certified_rate` = predicted `CERTIFIED` claims whose gold status is not `CERTIFIED`, divided by predicted `CERTIFIED` claims; `over_withholding_rate` = gold `CERTIFIED` claims predicted not `CERTIFIED`, divided by gold `CERTIFIED` claims. Both with Wilson intervals.
- **Cost:** total calls and tokens, and per case.

`run_evals.py` CLI: `python -m pcd.evals.run_evals --cases data --backend oracle|noisy --seed 0 [--no-verifier] [--out results/]`. It prints a markdown summary table and writes `results.json`. A `--compare` flag runs noisy with and without the verifier and prints both side by side (the ablation).

Note for the printed output: with 10 cases the intervals are very wide. Print a one-line caveat saying so.

## 7. Case generator (pcd/data/generate_cases.py)

Fully offline and deterministic: `python -m pcd.data.generate_cases --out data --seed 7`. Writes one `Case` JSON per line using `pcd/schemas.py`.

**Gold labels are written directly per case template, not computed by `rules.py`.** Two independent encodings (the template and the rules) are cross-checked by a test.

**Document format** (rendered from templates, with a seeded choice among phrasing variants):

```
SYNTHETIC TEST DOCUMENT
Title: <title>
Owner: PAYER | Type: CONTRACT_EOC | Effective: 2026-01-01 | Supersedes: none
Applies to: Plan NW-Gold, Florida, member setting      <- header line for about half the docs

<2 to 4 sentences stating the value, in one of at least 2 phrasing variants per topic and value>
(for the other docs the scope is stated only in the prose, e.g. "This section covers Plan NW-Gold members in Florida.")
```

Use at least 2 phrasing variants per topic per value. Values use the normalized formats in `schemas.py`. Fictional plans: `NW-Gold`, `NW-Silver`. Dates are ISO. `Effective:` may be `2025-01-01 to 2025-12-31` for a closed range.

## 9. Tests and acceptance criteria

`pytest -q` must pass with no network and without crewai installed.

1. **Rules vs gold** (`test_data.py` or `test_rules.py`): for every gold pair in the sample file, `rules.decide_resolution`, the three checks, the implied route, and `statuses_from_resolution` agree with the gold values written by the generator.
2. **Oracle run is perfect**: OracleBackend plus OracleReviewer on all 10 cases gives extraction accuracy 1.0, detection F1 1.0 for every label present, `routing_accuracy` 1.0, `risky_auto_resolved` 0, `wrong_certified_rate` 0, `over_withholding_rate` 0.
3. **Zero risky auto-resolves, for any seed**: for seeds 0 to 49, with NoisyBackend at default and at very high error rates (every rate 0.9), `risky_auto_resolved` is 0. This is the structural guarantee.
4. **Determinism**: the same seed gives byte-identical `results.json`; different seeds usually differ.
5. **Errors are reported honestly**: with `detect_label_error=1.0`, the detection accuracy reported is 0.0 (the guardrail and reviewer may still fix the end-to-end outcome; assert on detection metrics only).
6. **Metrics unit tests** with hand-built predictions: known confusion matrices give the exact expected precision, recall, F1; `wilson_interval(8, 10)` is within 0.001 of `(0.490, 0.943)`; `wilson_interval(0, 0)` is `(0.0, 1.0)`.
7. **Data**: the sample file has exactly 10 valid `Case` records; ids unique; every document contains `SYNTHETIC TEST DOCUMENT`; every `claim_id` is `f"{doc_id}:{topic}"`; at least 40% of documents state their scope only in the prose and not in an `Applies to:` header line; the generator output is deterministic for a fixed seed.
8. **Verifier ablation sanity**: with the same seed and a high `detect_label_error`, running with the verifier gives an equal or lower `wrong_certified_rate` than without it, averaged over seeds 0 to 49.
9. `python -m pcd.evals.run_evals --cases data --backend oracle` runs and prints the summary.

## 10. Style

Small, readable, typed functions. Short docstrings that say why. No dead code. No comments that restate the code. Do not add features beyond this spec.

## 11. Known open points (decided here, review later)

- Check 3 is defined here as "equal authority across different owners". The proposal page words it more loosely as a tie between equal-authority sources.
- The simulated reviewer is an oracle. A real run would sample reviewer error and queue delay.
- One claim per document in the 10 sample cases. Multi-claim documents come with the 100-case set.
- The single-call baseline, a "no verifier" CrewAI variant and the LLM-rendered prose for the 100 cases are deferred.
